# Looper

ループ辺を、元メッシュの形状を保ったまま動かす Blender アドオン。

コーンなどにループカットを入れて `R` で回すと断面が元の面からはみ出して
形が崩れる。Looper はループの各頂点を「上下の隣接頂点を結ぶ線分（レール）」へ
射影し直して、元の形状を厳密に復元する。

## 現状（v0.4）

### Looper Rotate（モーダル / 本命）

`Alt+R`、または N パネル > Looper タブ、`Ctrl+E`、右クリックメニュー。
ドラッグ中ずっと形状が保たれたまま、頂点が既存辺の上を滑る。

ピボットはループの重心、軸は既定でビュー方向（標準の `R` と同じ感覚）。

| キー | 動作 |
|---|---|
| `X` / `Y` / `Z` | グローバル軸に拘束（同じキーで解除） |
| `Ctrl`（押している間） | スナップ（[下記](#スナップctrl)） |
| `S` | スナップ先を切り替え（刻み → 面 → ループ） |
| `Shift` | 精密モード（1/10）。`Ctrl` 併用時は 1° 刻み |
| 数値 / `Backspace` | 角度を直接入力（度）。軸拘束中は**絶対角度**として解釈 |
| `A` | 数値入力の絶対 / 相対を切り替え（軸拘束中のみ） |
| `P` | モード切り替え（平面断面 / 最近点） |
| `E` | Extend Past Neighbors のトグル |
| `LMB` / `Enter` | 確定 |
| `Esc` / `RMB` | 中止（完全復元） |

### `Alt+R` が反応しないとき

NVIDIA App では `Alt+R` が「パフォーマンス オーバーレイの表示切り替え」に
既定で割り当てられている。ドライバのオーバーレイがグローバルフックでキーを
先に受け取るため、Blender までイベントが届かない。

- NVIDIA App > 設定 > **オーバーレイ** を OFF にする
  （設定 > **キーボードショートカット** から「パフォーマンス オーバーレイ」の
  キーを変更・解除するだけでもよい）
- オーバーレイの設定を変えたくない場合は、N パネル > Looper タブ、`Ctrl+E`、
  右クリックメニューから実行する

AMD の Radeon Software でも `Alt+R` が Radeon オーバーレイの既定キー。

### スナップ（`Ctrl`）

`Ctrl` を押している間だけスナップ状態になる。何にスナップするかは
モーダル中に `S` で切り替えられる（N パネル > 設定 > `Ctrl:` が既定値）。
Blender の磁石アイコンと同じ考え方で、**`Ctrl` = スナップ**は固定し、
スナップ先だけを切り替える形にしてある。

- **Increment** … 角度を 5° 刻みに丸める。`Shift` 併用で 1° 刻み
- **Face** … カーソル下の面の法線にループを揃える
- **Loop** … カーソル下のエッジループの平面にループを揃える。指した位置に
  最も近い辺からエッジループを辿り、そのループに平面をフィットする

`Face` と `Loop` の間はマウスの役割が変わる。どちらもカーソルで対象を指すので、
その間は回転の積算が止まる。`Increment` はマウスが回転を駆動したまま、
値だけが丸められる（Blender 標準の `Ctrl` と同じ）。

`Face` と `Loop` は別物。`Face` はループ平面を**その面と平行**にし、
`Loop` はループ平面を**そのループの平面と平行**にする。段差や縁取りで
「隣のループと同じ傾きに」したいときは `Loop`（面では代替できない）。

`Ctrl` を離すと素の回転に戻る（Blender 標準のスナップと同じ）。
軸拘束中は拘束を破らず、その軸で回れる範囲で目標に最も近づく角度になる。

動かしているループに接する面はスナップ先から除外され、`Loop` では辿った
ループに動かす頂点が含まれていたら拒否する。動いているものに揃えようと
すると参照が循環するため。

N パネルの設定は `Alt+R` で起動したときにも反映される。

### 絶対角度

`X` / `Y` / `Z` で軸拘束している間は、ヘッダに**ループ平面の絶対的な傾き**が
出る。ここで言う角度は断面の平面の傾きであって、頂点がレール上を進んだ量では
ない。

この状態では数値入力が**絶対角度の指定**になる。`X` → `30` → `Enter` で
「XY 平面に対して 30 度」、`X` → `0` → `Enter` で XY 平面と平行。

**既定が絶対**なので、`A` を押すと相対に切り替わる（「X 軸まわりにあと 10 度」）。
どちらで解釈されるかはヘッダの `数値:絶対` / `数値:相対` に出る。

- `X` / `Y` 拘束時は **XY 平面（法線 Z）を 0 度**として測る
- `Z` 拘束時は Z を基準にできないので **YZ 平面（法線 X）を 0 度**とする
- 平面は 180 度回すと元に戻るので、表示は常に **-90°〜+90°** に畳まれる

軸拘束が無いとき（ビュー軸）は基準が視点依存になって意味を失うため、
数値入力は常に相対。角度は 1 自由度、法線は 2 自由度なので、絶対指定は
「どの軸まわりか」が決まっていないと姿勢が定まらない。

オブジェクトに非一様スケールが掛かっていると、絶対角度は回転量に対して
加算的でなくなる（ローカル空間の軸回転がワールドでは剪断を伴う）。
差の引き算ではなくニュートン法で解いているので、その場合も指定どおりになる。

### 画面表示

モーダル中は、値と状態をヘッダに、キー一覧を画面下部のステータスバーに
出す（Blender 標準の `R` / `G` と同じ構成）。

```
回転    +12.30°   絶対    +25.00° (XY)   数値:絶対   軸 X   Ctrl:面   平面断面 · 越境ON
```

3D ビューには次を描く。

- **拾ったスナップ先**（橙）… ホバー中の面、または拾ったエッジループ。
  「指した位置に最も近い辺」で決まる以上、見えないと確かめようがない
- **拘束軸**（X=赤 / Y=緑 / Z=青）… ピボットを通る線
- **平面に届かなかった頂点**（赤い点）… 下記

### レール端で止まったとき

目標平面がレールと交差しない場合（平面がレールとほぼ平行になるなど）、
その頂点はレールの端で止まる。結果は平面に乗らないので、**ヘッダに
「○ 頂点が平面に届いていません」と表示され、該当頂点が赤い点で示される**。
揃ったつもりで揃っていない、を黙って通さないための表示。

### Flatten Loop（平面化）

非平面に歪んだループを、そのループ自身のベストフィット平面へ揃えて平らにする。
N パネル > 揃える、`Ctrl+E` / 右クリックメニューから。

### Fix Loop to Rails（事後補正 / 救済用）

普通に `G` / `R` / `S` で崩してしまったあと、レール上へ引き戻す。
`Ctrl+E` / 右クリックメニューから。

## 2つのモード

### Plane Section（既定）

ループ全体に最小二乗で平面をフィットし、それを傾けて、**各レールとその平面の
交点**を新しい頂点位置にする。

- 断面が必ず平面になる
- コーンなら数学的に正しい楕円断面（頂点は円錐面上に厳密に乗る）
- 指令角度と実際の傾きが 1:1（飽和しない）
- 視線方向を向いたレールの頂点もちゃんと滑る

### Nearest Point

剛体回転した理想位置から、**頂点ごとに独立して**レールへ最近点射影する。

- 元から非平面なループでも動く
- 断面は平面にならない（サドル状に歪む）
- レールの向きによって滑り量が偏り、角度を上げると効きが飽和する

通常は Plane Section。ループが元から平面でない場合や、頂点ごとの局所的な
挙動が欲しい場合に Nearest Point。

## オプション

- **Extend Past Neighbors** (default ON)
  レールを隣のループの先まで辿る。OFF にすると直近の1区間でクランプ。

## アルゴリズム

スナップショット不要。動いたのはループ頂点だけで、レールの端点（上下の
隣接ループの頂点）は動いていないため、線分は編集後のメッシュから復元できる。

1. 選択頂点 v について、非選択の隣接頂点への辺をレール候補にする
   （3本以上ある場合は最も反平行なペアを採用）
2. `extend` 時は valence 4 の頂点を辿ってエッジリング方向へ折れ線を延長
3. v を折れ線上の最近点へ射影

Plane Section とスナップ系は、いずれも「**目標平面 (法線, 通過点) を決めて、
各レールとの交点を取る**」という一つの操作に還元される。回転行列は目標平面を
作る手段でしかないので、`Ctrl+ホバー`（姿勢を直接指定）も数値入力（絶対角度）も
新しい経路を増やさずに同じ場所へ合流する。

姿勢を直接指定するものは、いったん `(軸, 角度)` へ逆算してから適用している。
そのおかげで F9 のリドゥ、ヘッダの角度表示、スナップ解除後の継続が、
通常の回転とまったく同じコードを通る。

## テスト

```
blender --background --factory-startup --python tests/test_core.py
blender --background --factory-startup --python tests/test_modal_core.py
blender --background --factory-startup --python tests/test_plane_mode.py
blender --background --factory-startup --python tests/test_align_core.py
```

`Looper/core.py` は `bpy` に依存しないので（`bmesh` / `mathutils` のみ）
ヘッドレスでそのまま検証できる。スナップのピッキングも、マウス座標の計算だけを
外して実際に BVH へレイを飛ばす形でテストしてある。

Blender 4.2 LTS と 5.1 で確認。
